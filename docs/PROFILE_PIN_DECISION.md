# Profile Pin Decision

Checkpoint:
`CLIENTDELIVERYKIT-011-PROFILE-PIN-OR-MAINTAIN-SHOWCASE-DECISION-COMPLETE`

## Decision

Pin decision: `recommend pin`

ClientDeliveryKitAgent is a strong GitHub Profile pin candidate if a slot is
available. It should not replace AgentHubControlCenter as the main hub pin.
AgentHubControlCenter explains the full Agent portfolio system; ClientDeliveryKitAgent
shows the client-facing delivery workflow that a business-oriented AI automation
consultant could hand to a stakeholder.

## Why Not Strongly Recommend Pin

`strongly recommend pin` remains reserved for AgentHubControlCenter because it
is the portfolio hub and system architecture proof. ClientDeliveryKitAgent is
the strongest applied spoke, but it is still a spoke.

## Recommended Pinned Order

1. AgentHubControlCenter: main hub / AgentOps Command Center.
2. ClientDeliveryKitAgent: client-facing AI automation delivery workflow.
3. BusinessOpsAgent: SME operations and workflow automation proof.
4. SocialPainFinderAgent: pain-point discovery and business opportunity proof.
5. QuantLabAgent: analytical rigor, risk framing, and dashboard depth.
6. NewsSignalAgent or CareerPilotAgent: signal analysis or practical user-facing workflow.

If the GitHub profile already has six pinned repositories, do not change pins
automatically. The replacement choice should remain manual and based on the
portfolio story the user wants to emphasize.

## Relationship To AgentHubControlCenter

| Project | Portfolio Role | Pin Priority |
| --- | --- | --- |
| AgentHubControlCenter | Main hub / AgentOps Command Center | First |
| ClientDeliveryKitAgent | Client-facing delivery workflow spoke | Second if a slot is available |

## Manual Decision Rule

- Pin ClientDeliveryKitAgent when the portfolio needs to emphasize consulting,
  client delivery, workflow diagnosis, and business-facing AI automation.
- Keep it unpinned but linked from AgentHubControlCenter when there are no free
  pin slots or when the profile should emphasize the overall AgentOps system.
- Do not add product features only to justify a pin. The current public
  showcase is already sufficient.

## Final Recommendation

Use `recommend pin` with maintain-showcase status. Manual GitHub pinning is
optional; feature expansion should pause.
